PHASE 02 — STEP 04 CORRECTION
ROLES & CREDITS — PRACTICAL USER DATA ENTRY

The database foundation for Roles and Credits was implemented in Phase 02 Step 04.

However, an important product requirement was not completed:

The user must be able to MANUALLY ENTER, VIEW, EDIT, and REMOVE role/contribution data from the existing Naghme UI.

The current implementation has the data model and query layer, but the user cannot practically populate Credits from the app.

This correction is specifically for making the existing Roles/Credits functionality usable.

DO NOT rebuild Naghme.
DO NOT reset the database.
DO NOT change the existing Phase 02 data model unless a real bug requires it.
DO NOT create fake Credits.
DO NOT fabricate historical music metadata.
DO NOT introduce unrelated features.
DO NOT start Phase 03.
STOP after this correction is complete.

==================================================
1. CORE PRODUCT PRINCIPLE
==================================================

Naghme is a manually curated personal music archive.

If the user adds a new metadata field or relationship, the application must provide a practical way for the user to enter that information.

Therefore:

Database field alone = NOT sufficient.

Every new user-facing archive datum must have:

ADD → SAVE → DISPLAY → EDIT → DELETE

functionality where appropriate.

For Roles/Credits this means the user must be able to manually create and manage contributions.

==================================================
2. DO NOT CONFUSE ARTIST ROLES WITH CREDITS
==================================================

There are two related but different concepts.

A) General artist roles:

Example:

Ali Tajvidi
- Composer
- Arranger
- Musician

This describes roles the artist may have in the archive.

B) Specific Credit:

Example:

Track: "Mara Bebus"

Ali Tajvidi → Composer
Rahim Moayeri → Lyricist
Delkash → Vocalist

This describes what a specific artist did for a specific Work, Track, or Album.

The current Roles/Credits database model must remain the source of truth.

Do not create separate composer/lyricist/vocalist tables.

==================================================
3. ARTIST ADD / EDIT UI
==================================================

Inspect the existing Add Artist and Edit Artist screens.

Add a practical section for the artist's general roles if the current product model supports it.

The user should be able to:

- see available roles
- select multiple roles for an artist
- add/remove roles
- save them persistently

Use the existing Roles table.

Do NOT create duplicate role definitions.

Do NOT automatically create Work/Track/Album Credits from these general roles.

General artist role ≠ specific Credit.

If the existing data model does not currently have a dedicated relation for general artist roles, DO NOT invent a second role architecture unnecessarily.

In that case, prioritize the specific Credit workflow described below.

==================================================
4. TRACK ADD / EDIT UI — REQUIRED
==================================================

This is the most important part.

Inspect the existing Add Track and Edit Track forms.

Add a section such as:

"مشارکت‌کنندگان"

or

"عوامل و نقش‌ها"

The exact visual wording can follow the existing Naghme UI language.

The user must be able to:

- add a contributor
- select an existing Artist
- select a Role
- save the Credit
- see all Credits currently attached to the Track
- edit a Credit
- remove a Credit

Example:

Track:
مرا ببوس

مشارکت‌کنندگان:

دلکش       — خواننده
علی تجویدی — آهنگساز
رهی معیری  — ترانه‌سرا
فلانی      — تنظیم‌کننده

Provide:

"+ افزودن مشارکت"

When pressed:

1. Select Artist
2. Select Role
3. Optional notes
4. Save

Do NOT require the user to manually enter Artist IDs or Role IDs.

Use human-readable names.

The artist selector should use existing Artists.

The role selector should use existing Roles.

If no Artist exists, provide an appropriate empty state directing the user to add an Artist first.

If no Role exists, use the existing seeded Roles.

Do not fabricate contributors.

- Version
