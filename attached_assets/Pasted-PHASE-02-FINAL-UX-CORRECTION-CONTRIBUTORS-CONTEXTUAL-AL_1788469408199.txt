PHASE 02 — FINAL UX CORRECTION
CONTRIBUTORS + CONTEXTUAL ALBUM FILTERING + CREATE-FORM WORKFLOW

This is a final UX correction to the existing Naghme Phase 02 implementation.

DO NOT start Phase 03.
DO NOT redesign the architecture.
DO NOT reset, rebuild, or delete the database.
DO NOT remove or replace the existing Roles/Credits model.

The goal is to make the existing Roles/Credits functionality genuinely usable from the user-facing Add/Edit workflows and fix the Artist → Album selection logic.

2. CRITICAL UX RULE — CONTRIBUTORS MUST BE ENTERED DURING CREATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The current workflow is NOT acceptable if it behaves like:

Add Track
→ Save Track
→ Reopen/Edit Track
→ Add Contributor

or:

Add Album
→ Save Album
→ Reopen/Edit Album
→ Add Contributor

Do NOT require the user to save the entity first just to unlock the Contributors section.

The user must be able to enter Contributors directly inside the initial Add form.

Correct workflow:

Add Track
→ enter Track information
→ select Artist
→ select Album
→ add one or more Contributors
→ select their Roles
→ Save ONCE

Similarly:

Add Album
→ enter Album information
→ add one or more Contributors
→ select their Roles
→ Save ONCE

The user should be able to provide all relevant information they know at the moment of creation.

The initial creation form must NOT display messages such as:

"ابتدا قطعه را ذخیره کنید تا مشارکت اضافه شود"

or:

"ابتدا آلبوم را ذخیره کنید تا مشارکت اضافه شود"

Those messages must be removed from the creation workflow.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Add Track form must contain a dedicated:

"مشارکت‌کنندگان"

section BEFORE the final Save action.

The user can add multiple contributor rows.

Each contributor row must contain:

- Artist selector
- Role selector
- Optional notes
- Remove button

The user must be able to select existing Artists and Roles without manually entering IDs.

Example:

مشارکت‌کنندگان

[ علی تجویدی ▼ ] [ آهنگساز ▼ ] [ حذف ]

5. TECHNICAL SAVE WORKFLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

New entities do not have database IDs before creation.

Therefore, do NOT create fake database records or fake permanent IDs just to support the form.

Use temporary form state, for example:

pendingCredits[]

During Save:

1. Validate the entity fields.
2. Validate pending Contributors.
3. Create the Track or Album.
4. Obtain the newly created entity ID.
5. Create the corresponding Credit records using that ID.
6. Commit the operation.

Prefer a single database transaction:

BEGIN
→ create entity
→ create Credits
→ COMMIT

If any part fails:

ROLLBACK

The user should experience this as one Save operation.

Do not leave behind a partially-created Track/Album with missing Contributors when the transaction fails.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

10. ARTIST → ALBUM CONTEXTUAL FILTERING

In the Add Track form, when the user selects an Artist, the Album selector must become contextual to that Artist.

The Album selector must NOT show every Album in the database.

Example:

Selected Artist:
Delkash

Available Albums:
- Album A — associated with Delkash
- Album B — associated with Delkash
- Album C — associated with another artist

The Album selector must show only:

- Album A
- Album B

Album C must NOT appear.

The user must never accidentally attach a Track by Artist A to an unrelated Album belonging to Artist B simply because that Album exists in the global Album list.

- AlbumTracks

Do not fabricate associations merely to populate the picker.
