--------------------------------------------------
PROJECT CONTEXT
--------------------------------------------------

Naghme is a personal digital music archive.

It is NOT intended to become a Spotify clone.

The long-term vision is a serious personal music archive combining:

- music library
- cultural/music archive
- artist encyclopedia
- work and recording catalog
- personal music journal
- listening history
- music relationships
- visual music graph
- AI assistant
- artwork/poster archive

The existing project is already functional and must NOT be rebuilt from scratch.

The current stack must remain:

- Expo React Native
- TypeScript
- Expo Router
- SQLite
- local/offline-first architecture
- Android-first

No backend or authentication should be introduced.

--------------------------------------------------
6. MUSIC DOMAIN REQUIREMENTS
--------------------------------------------------

The future architecture must eventually support:

A person can have multiple musical roles.

Examples:

- vocalist
- composer
- lyricist
- arranger
- musician
- conductor
- producer
- ensemble/group
- other

A single track may have many credits.

Example:

Track
├── vocalist → Person A
├── composer → Person B
├── lyricist → Person C
├── arranger → Person D
└── musician → Person E

Do NOT design around a single artistId field.

--------------------------------------------------
7. WORK VS RECORDING
--------------------------------------------------

Evaluate how the current system could distinguish:

WORK
= the underlying musical composition

TRACK / RECORDING
= a concrete recording/library item

VERSION
= a particular interpretation/version of a work

Example:

WORK
└── "Example Work"

TRACK / RECORDING
├── studio recording
├── live recording
├── radio recording
└── remastered recording

Determine the minimum practical architecture needed to support this later without over-engineering the current project.
